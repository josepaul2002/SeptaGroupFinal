# Content release rules

Public pages are generated from the same rule: `status=published` and `publication_reviewed=true`. A draft, restored revision or unverified credit is omitted from public API responses, initial HTML, sitemap and structured data.

## Before publishing a project

- Use the real project name, location, scope and completion state.
- Write the challenge, approach and outcome from approved project records.
- Add the responsible Septa lead and external contributors with role, contribution and permission to publish.
- Mark every public image, render and drawing as approved. Drawings stay private unless `plans_public` is enabled.
- Set a page title, description and social image, or leave them blank for generated metadata.
- Preview the record, then have a second person review the facts and permissions.

## Before publishing a profile or testimonial

- Confirm the person or organisation name, role and bio.
- Confirm portrait/logo and photographer or owner permission.
- Confirm client testimonial wording, attribution and project reference.
- Use the SEO preview and check the related project links.

The admin panel keeps revisions before updates, archives instead of deleting, and restores old records as drafts. Enquiry records remain durable when email is unavailable; the dashboard shows failed notification state and provides retry action.
